# Tali product principles

## Observe without judging

Tali records user-defined events and reports their timing and frequency. It does not decide whether an activity is good or bad, whether it should happen more or less often, or whether a user is succeeding.

This applies equally to exercise, medication, substances, chores, creative work, symptoms, relationships, and anything else a person chooses to track.

## Product rules

- Show facts: timestamps, elapsed time, counts, notes, and history.
- Never add goals, streaks, missed-day states, scores, praise, shame, warnings, or recommended frequency by default.
- Never describe more activity as progress or less activity as failure.
- Use neutral terms such as **entry**, **history**, **timeline**, **most recent**, and **count**.
- Avoid success-coded checkmarks, celebration, and green-as-reward for ordinary entries.
- Let users choose every habit. New accounts start empty.
- Preserve the user's own wording without classifying or euphemizing it.
- Make corrections and undo straightforward and factual.
- If optional reflection or goal features are ever added, they must be explicitly chosen per habit and must not change the neutral default.

## Copy test

Before shipping user-facing copy, ask: “Does this sentence imply that the user should do this activity more often, less often, or feel a particular way about it?” If yes, rewrite it as a factual description of the recorded data or action.
